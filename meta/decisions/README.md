# Seed-meta Architecture Decision Records

ADRs documenting the seed's own design choices — separate from `docs/decisions/`, which is for adopter projects' ADRs (`docs/decisions/README.md` for conventions; this directory uses the same conventions).

See [`../README.md`](../README.md) for what the `meta/` directory is and how adopters handle it.

## Index

Revision: re-pinned to the `main` node24 commit and `actions/checkout` `@v4`→`@v5` for the Node-20 runner deprecation.
- [ADR-0002](ADR-0002-active-trivial-ci-workflow.md) — Ship an active trivial CI workflow with four-tier framing in comments — Accepted — `.github/workflows/ci.yml` runs four tier-3 jobs on the seed itself (markdown lint, internal link check, dangling-placeholder audit, workflow YAML lint); tiers 1/2/4 are commented stubs adopters extend.
- [ADR-0003](ADR-0003-labels-applied-via-reviewer.md) — Label-vs-diff checking via the reviewer subagent (not a CI gate); pre-applied issue templates — Accepted — pre-push reviewer prompt extended with label-vs-diff + lifecycle currency bullets; `.github/ISSUE_TEMPLATE/` ships `decision-proposal.yml` and `bug.yml` with pre-applied labels; CI merge-gate (A) deferred with three named revisit conditions.
- [ADR-0004](ADR-0004-pre-push-ci-via-ecosystem-task-runner.md) — Pre-push CI invocation via the ecosystem's own task runner — Accepted (Revised 2026-06-18) — `CONTRIBUTING.md §"Pre-push CI run"` recommends defining CI commands once in the ecosystem's task runner (tox / cargo / npm scripts / etc.) and calling them from both the workflow and the pre-push invocation; `act` reframed as a niche tool; tier 1 + tier 3 only pre-push (~30s budget). Revision: the seed dogfoods `scripts/local-ci.sh` over its own heterogeneous doc-CI (the "no ecosystem runner fits" fallback); adopter recommendation unchanged.
- [ADR-0005](ADR-0005-branch-protection-as-code-classic.md) — Branch protection as code: classic schema + human-triggered apply + scheduled drift check — Accepted — `.github/branch-protection.yml` is the desired state; `scripts/setup-branch-protection.sh` applies it using the operator's `gh auth` credentials (no admin PAT secret); `.github/workflows/check-branch-protection.yml` runs weekly read-only drift detection.
- [ADR-0006](ADR-0006-meta-folder-for-seed-history.md) — Separate seed-meta from adopter template content via `meta/` — Accepted — moves the five preceding ADRs and the seed's CHANGELOG into `meta/`; adopters strip-or-keep via the README's *How to adopt* step.
- [ADR-0007](ADR-0007-v-cycle-additions.md) — V-cycle-shaped additions to the right side: V&V split, per-rule verified-by, optional RISKS.md — Accepted — `REVIEW_CONTEXT.md` names verification vs validation review modes; `SPEC.md` adopts a `verified by:` convention for binding rules; `docs/RISKS.md` ships as the seed's first explicitly-optional document. Stable SPEC IDs and multi-doc baseline versioning deferred with named revisit conditions.
- [ADR-0008](ADR-0008-reviewer-invocation-convention.md) — Parameterised reviewer-invocation convention for open PRs, with CI-aware fallback and follow-through-by-default subscription — Accepted — `CONTRIBUTING.md §"Reviewing an open PR"` parameterises the invocation across six levers (PR number, mode, output channel, context-doc set, CI handling, subscription) with conservative defaults; CI-handling fallback chain (green → summarise; red → fetch logs; unreachable → local tier-1+3; `skip` → disclose) avoids silently skipping right-side mechanical checks; `subscribe` as default keeps the reviewer responsive through the PR lifecycle.
- [ADR-0009](ADR-0009-agent-pr-lifecycle-and-two-session-workflow.md) — Agent PR lifecycle: open/merge gate + two-session authoring / review workflow — Accepted — `CLAUDE.md §5` makes opening a PR free for in-plan work but merging always maintainer-gated; `CONTRIBUTING.md §"Two-session authoring / review workflow"` defines the authoring/reviewing split (three verbs, 5-step loop, command vocabulary) and scopes the *push-a-fix* instruction to the single-session model; repo policy doesn't self-bind a session (the grant comes from session launch). Forward-ported from `ppqq-active`.
- [ADR-0010](ADR-0010-analyses-doc-type.md) — `analyses/` as a first-class optional doc type — Accepted — `docs/analyses/README.md` ships the four-rule convention (dated filename, anchored-to-a-commit, immutable-once-merged, not-a-contract) plus three usage models (snapshot series, marked canonical registers, periodic review→issues→remediation loop); seed dogfoods it as `meta/analyses/`. Backported from the four-adopter study (all four converged).
- [ADR-0011](ADR-0011-contract-gate-catalogue-and-drift-hardening.md) — Contract-gate pattern catalogue + drift-hardening doctrine — Accepted — `CONTRIBUTING.md §"CI strategy" §1` gains a rendered nine-pattern catalogue (incl. shared contract artifact, preferred over mirror+equality where feasible), two failure-mode caveats (gate the production idiom; cross-check `Verified by:` claims), machine-shared-artifact hardening (generator provenance + tolerance floor + no orphans), and the three-line doctrine; contract-change checklist gains the paired prose-refresh step. Backported from ppqq + tombo + sid.
- [ADR-0012](ADR-0012-known-bug-lifecycle-two-mechanisms.md) — Known-bug lifecycle: two mechanisms, presented as options — Accepted — `CONTRIBUTING.md §"Known-bug lifecycle"` presents self-healing xfail tests (adigator) and visible-debt markers + register (tombo, sid) unranked, each with its residual debt; common core mandatory either way, as a PR-checklist row: a bug fix closes its tracking artifact in the same PR. Supersedes the xfail-only two-adopter decision.
- [ADR-0013](ADR-0013-discipline-adoption-marker.md) — `DISCIPLINE_ADOPTION.md` adoption / sync marker — Accepted — root-level template recording seed provenance (pinned `vX.Y.Z (sha)` + profile), per-artifact adoption table, append-only sync log, optional backport log; committed file default, pinned tracking issue allowed (sid's counterpoint); two optional companions (adoption-display sentence; upstream backport-suggestion issues); seed starts cutting git tags at CHANGELOG versions. Named for the discipline, not the seed, per maintainer review.
- [ADR-0014](ADR-0014-randomized-exploration-convention.md) — Randomized-exploration testing convention (PBT / Monte-Carlo) — Accepted — `CONTRIBUTING.md §"Randomized-exploration testing"` carries the three convergent rules (invariants/oracles, never a reimplementation; seeded reproducibility, failures promoted to committed deterministic fixtures; unbounded campaign out of the PR gate) plus the mandatory floor for adopters: forced runs at phase completion (`PHASE-TEMPLATE §10` Admin) and via the major-bug/feature PR-checklist row; scheduled CI as optional hardening. Promoted from Tier 2 by maintainer decision in the PR #37 review.
- [ADR-0015](ADR-0015-release-as-code.md) — Release-as-code: tag-push workflow with a CHANGELOG gate and a curated template archive — Accepted — `.github/workflows/release.yml` fires on `v*` tag pushes, validates the tag against the CHANGELOG (dated `## [X.Y.Z]` section present + `[Unreleased]` empty, via the dry-runnable `.github/scripts/release_changelog.py`), extracts the section as the release body, and attaches a `meta/`-stripped `<repo>-vX.Y.Z-template.zip`/`.tar.gz`. Human-decides / machine-executes (as ADR-0005); turns ADR-0013's tag convention into a structural gate; first `contents: write` workflow, scoped to tag pushes; branch protection untouched (runs on tags, not PRs). Rejected: manual dispatch, release-on-merge, a packaged release action, inline gate one-liners.

CI gate (#57) and advisor-model runtime escalation deferred with named triggers.
